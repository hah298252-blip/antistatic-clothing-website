## 修复首页第五屏旅程线无法完整绘制的问题（ScrollJourney）

- 根因：`ScrollJourney.css` 中 `vector-effect: non-scaling-stroke` 会使浏览器在**屏幕像素空间**计算描边几何（含 dash 图案），而 `ScrollJourney.jsx` 用的 `path.getTotalLength()` 返回的是 viewBox 用户单位长度。SVG 为 `viewBox="0 0 100 1000"` + `preserveAspectRatio="none"` 拉伸铺满 500svh 容器，用户单位长度约为屏幕实际长度的 1/4，导致 dasharray 只覆盖路径一小段，滚动时只是虚线段在滑动，永远画不完整。
- 修复：在 JS 中采样 `getPointAtLength` 并按 SVG 实际渲染的 scaleX/scaleY 换算，测出屏幕空间真实路径长度来设置 `stroke-dasharray/dashoffset`；用 `fromTo` + 函数式起始值 + `invalidateOnRefresh` + `onRefreshInit` 重新测量，保证 resize 后同步。
- 顺带改进：三个节点（证书/展会/报告）的出现时机由写死的 [0.16, 0.51, 0.85] 改为按"线画到该节点高度时的路径进度"计算（`progressAtY`）。
- 保留 `non-scaling-stroke`（保证 2.5px 线宽在非均匀拉伸下恒定），已在 CSS 中加注释禁止移除。
- 验证：`vite build` 通过（本机 dist/ 清理会被安全删除拦截，验证构建改用临时 outDir）。

## 重写产品页拖拽网格 + 详情 Flip 动效（Products）

- 根因（与原教程效果差距大）：
  1. `InertiaPlugin` 未注册，`inertia: true` 实际上不生效，拖拽没有惯性。
  2. 只有 6 个产品 / 3 列，网格宽度（65.5vw）小于视口，导致 Draggable 的 `minX > maxX`，边界失效，根本拖不动。
  3. 没有关闭详情动画，点击产品打开后页面卡住，无法回到网格。
  4. React 里直接用 `appendChild` 移动 DOM 节点，离开页面时可能炸树。
- 修复：
  1. 注册 `InertiaPlugin`。
  2. 用现有 14 张 PNG/JPEG 产品图拼成 5 列 × 3 行 = 15 个单元格，网格宽度 110.5vw、高度约 1.34 倍视口，拖拽边界正常，滚动/拖拽时产品淡入淡出效果明显。
  3. 补上 `hideDetails()`：用 Flip 把产品动画回原列、网格滑回、详情面板退出，并重新启用拖拽和 IntersectionObserver。
  4. 加关闭按钮；用 `originalNextSibling` 把产品插回原来位置，避免 React 树异常。
  5. 阻止“拖拽时误触发点击打开详情”：用 Draggable 的 `onDragStart` / `onPress` 标记 `wasDragging`，点击时过滤。
  6. resize 时重新计算边界并 `applyBounds`，但详情打开时不重置网格位置。
  7. `.detailsThumb` 内产品用 CSS 强制填充 100%（避免停留在 18.5vw）。
- 文件改动：`src/pages/Products.jsx`、`src/pages/Products.module.css`。
- 验证：`vite build` 通过。
